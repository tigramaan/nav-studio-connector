Release governance

Code signing policy.

Last updated: August 28, 2026

This policy defines who may change, review, approve, build, and sign releases of UMEC Nav Studio Connector.

Signing provider

The project is applying to the SignPath Foundation open-source program. Once accepted, signed releases will carry the required attribution: “Free code signing provided by SignPath.io, certificate by SignPath Foundation”. Until onboarding is complete, release artifacts are explicitly identified as unsigned and must not be represented as SignPath-signed.

Team roles

Committer and reviewer
tigramaan maintains the repository and reviews changes from external contributors before merge.
Signing approver
tigramaan verifies the release source, public build result, artifact identity, version, and security gates before manually approving a signing request.

All members with source-repository or SignPath access must use multi-factor authentication. A contributor may author a pull request, but cannot bypass required review or release approval.

Trusted build and provenance

Release binaries are built from the public repository by GitHub Actions. The trusted workflow checks out an exact revision, builds the Windows executable and NSIS installer, verifies tests and security gates, submits only those artifacts for signing, verifies Authenticode and timestamp results, and then publishes the approved files. Private signing keys are never stored in this repository or exposed to the build job.

Approval rules

Every production release requires manual approval. The approver must confirm that the revision belongs to this project, public CI is successful, product name and version metadata match the release, the artifact contains no proprietary project component, and SHA-256 evidence is recorded. A failed, missing, mismatched, untrusted, or untimestamped signature blocks publication.

Scope

Only binaries built from source maintained in this repository may be signed under this policy. Unsigned upstream open-source runtime components may be packaged where permitted, but are not submitted as project-owned binaries. The signing service must not be used for unrelated software, forks not governed by this team, or privately supplied executables.

Privacy

This program will not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it. Detailed local processing, storage, website hosting, and third-party destination behavior is documented in the privacy policy.

Installation and removal

The Windows package provides a standard per-user installer and registered uninstaller. The connector announces certificate-store changes before execution and removes only trust records identified as connector-owned. Platform commands and acceptance procedures are documented in the public repository.

Policy changes

Changes to release signing, trusted-build configuration, artifact scope, roles, or security gates must be reviewed like source changes and published before they govern a signing request.
